Matrix — Mensajería privada

Instalación de Matrix/Synapse con PostgreSQL y Caddy en Ubuntu Server 192.168.101.50 para una mensajería instantánea completamente privada y autoalojada.

Paso 1 — Instalación de dependencias

Nos convertimos en root, actualizamos los paquetes e instalamos todas las dependencias necesarias para Matrix/Synapse:

apt update && apt install -y lsb-release wget apt-transport-https \
build-essential python3-dev libffi-dev python3-pip python3-setuptools \
sqlite3 libssl-dev virtualenv libjpeg-dev libxslt1-dev libicu-dev \
libpq5 libpq-dev postgresql postgresql-contrib debian-keyring \
debian-archive-keyring apt-transport-https

Añadimos el repositorio oficial de Matrix e instalamos matrix-synapse-py3:

wget -O /usr/share/keyrings/matrix-org-archive-keyring.gpg \
  https://packages.matrix.org/debian/matrix-org-archive-keyring.gpg

echo "deb [signed-by=/usr/share/keyrings/matrix-org-archive-keyring.gpg] \
  https://packages.matrix.org/debian/ $(lsb_release -cs) main" | \
  tee /etc/apt/sources.list.d/matrix-org.list

apt update && apt install matrix-synapse-py3
Durante la instalación nos preguntará por nuestro dominio. Introducimos el nombre de dominio que queremos que aparezca en los usuarios: tosp-matrix.
Paso 2 — Configuración de PostgreSQL

Entramos como el usuario postgres y creamos el usuario y la base de datos:

sudo -u postgres bash

createuser --pwprompt synapse_user

createdb --encoding=UTF8 --locale=C \
  --template=template0 --owner=synapse_user synapse

exit

Editamos /etc/postgresql/12/main/postgresql.conf y buscamos el parámetro listen_addresses, al cual le añadiremos 'localhost'.

listen_addresses = 'localhost'

Luego editamos /etc/postgresql/12/main/pg_hba.conf y añadimos esta línea al final para activar la autenticación por contraseña:

local   synapse   synapse_user   md5

El bloque final del archivo quedará así:

local   replication   all              peer
host    replication   all   127.0.0.1/32   md5
host    replication   all   ::1/128        md5
local   synapse       synapse_user    md5
Paso 3 — Configuración de homeserver.yaml

Abrimos el archivo principal de configuración en /etc/matrix-synapse/homeserver.yaml. Primero borramos el bloque SQLite que viene por defecto:

database:
  name: sqlite
  args:
    database: /var/lib/matrix-synapse/homeserver.db

Y lo sustituimos por la configuración de PostgreSQL:

database:
  name: psycopg2
  args:
    user: synapse_user
    password: <contraseña>
    database: synapse
    host: localhost
    cp_min: 5
    cp_max: 10

Los parámetros principales del archivo completo son los siguientes:

server_name: "matrix-tosp"
public_baseurl: "https://<url-del-bastion>"
serve_server_wellknown: true
pid_file: "/var/run/matrix-synapse.pid"

listeners:
  - bind_addresses:
      - ::1
      - 127.0.0.1
    port: 8008
    resources:
      - compress: false
        names:
          - client
          - federation
    tls: false
    type: http
    x_forwarded: true

database:
  name: psycopg2
  args:
    user: tosp-admin
    password: PASSWORD
    database: synapse
    host: localhost
    cp_min: 5
    cp_max: 10
log_config: "/etc/matrix-synapse/log.yaml"
media_store_path: /var/lib/matrix-synapse/media
signing_key_path: "/etc/matrix-synapse/homeserver.signing.key"
trusted_key_servers:
  - server_name: "tosp-matrix"

registration_shared_secret: "<contraseña>"
enable_registration: true
enable_registration_without_verification: true

rc_registration:
  per_second: 9999
  burst_count: 9999
Los parámetros enable_registration y rc_registration permiten el registro libre de usuarios. Ajústalos según las necesidades de seguridad de tu entorno.
Paso 4 — Proxy inverso con Caddy

Un proxy inverso es un servidor intermedio que recibe las peticiones de los clientes y las redirige a Synapse. Caddy además gestiona automáticamente los certificados HTTPS mediante Let's Encrypt.

Añadimos los repositorios oficiales de Caddy e instalamos:

curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg

curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list

apt update && apt install caddy

Editamos /etc/caddy/Caddyfile, borramos todo el contenido y añadimos la siguiente configuración:

<url-del-bastion> {
    # Matrix client API
    reverse_proxy /_matrix/* localhost:8008 {
        header_up Host {host}
        header_up X-Forwarded-For {remote_host}
        header_up X-Forwarded-Proto {scheme}
    }

    # Synapse client endpoints (SSO, registro, etc.)
    reverse_proxy /_synapse/client/* localhost:8008 {
        header_up Host {host}
        header_up X-Forwarded-For {remote_host}
        header_up X-Forwarded-Proto {scheme}
    }

    # Fallback para el resto (incluido .well-known)
    reverse_proxy localhost:8008 {
        header_up Host {host}
        header_up X-Forwarded-For {remote_host}
        header_up X-Forwarded-Proto {scheme}
    }
}
Paso 5 — Arranque y verificación

Reiniciamos los tres servicios para aplicar todos los cambios:

systemctl restart caddy.service
systemctl restart postgresql.service
systemctl restart matrix-synapse

Si todo ha salido bien, al acceder a la URL del bastion en el navegador veremos la pantalla de confirmación de Synapse con el mensaje "It works! Synapse is running".

Para comprobar que Matrix funciona correctamente, accedemos a un cliente como Element o Cinny, seleccionamos Registrarse y en el campo Host account on introducimos la URL de nuestro bastion. Una vez creado el usuario ya podemos usar matrix para hablar con personas de nuestra organización.

Este servidor está configurado para uso interno. Los usuarios solo pueden comunicarse con cuentas del mismo dominio, ya que está pensado para la comunicación dentro de una organización, no con usuarios externos.
